## Verified root causes

1. crates/sdm-experiment/src/main.rs currently only accepts the command experiment run --config PATH. crates/sdm-experiment/src/lib.rs::run_semantic always calls train_typed_task, then writes a newly serialized artifact; evaluate_test=true only controls whether final labels are scored. Binary final baseline differs from frozen candidate in 38/100 weights (max delta 3.55e-15), and Binary mask differs in 41/100 (max 1.07e-14) plus minuscule bias. Encoders and train fingerprints match, but artifact BYTES do not. Numeric similarity is insufficient.
2. SemanticExperimentRunManifest.test_evaluation_performed has serde default=true and skip-true serialization. The original Python analyzer mistakenly requires an explicit true. It must not blindly infer true from missing field on arbitrary report formats; require validated legacy schema, exact test-case set and evidence.
3. scripts/analyze_m014_qualification.py stores binary[family][group][model] = one (label, probability), overwriting the other counterfactual member. Its Brier loop expects an array of pairs. The full frozen evaluator also lacks final negative-control and resource-gate adjudication. It produced no valid grouped CIs or qualified verdict.

Historical evidence: plans/closure/general-decision-model-framework/014-status.md and docs/m014-freeze-v1.json, docs/m014-protocol-v1.json, artifacts/m014/final-v1. Historical cohort is irrevocably consumed.

## A. Separate candidate fitting from frozen evaluation

A1. Introduce a distinct EvaluateSpec and command such as sdm-experiment experiment evaluate --config PATH. Do not treat evaluate_test=true on a training ExperimentSpec as evidence of frozen inference. Evaluation config requires named dataset/split and SHA-256, selected test membership SHA, protocol/freeze SHA, expected artifact byte SHA, exact semantic architecture and schema, known calibration fingerprint, and unique output path. It cannot accept epochs, learning rate, optimizer policy, re-fitting flags or artifact output path.
A2. The evaluation path uses bounded read-only artifact bytes, validates SHA-256 **before any case inference**, calls existing validated load_artifact, and reuses pure scoring logic extracted from run_semantic. NO reachable call to train_typed_task, train encoder, fit mask, choose threshold or write/re-serialize artifact. Immutable artifact bytes before/after evaluation must match exactly, not rounded/rehashed normalized tensors.
A3. Validate dataset/split provenance, disjoint leakage groups, exact expected test case IDs and group memberships, typed model schema, candidate/option IDs, calibrated task semantics, maximum 16 MiB v2 artifact, bounded options (128), finite scores and diagnostics. No training/test leakage or permission expansion. Reject missing SHA, unsupported architecture, duplicate output, corrupted artifact, modified case IDs, schema mismatch, nonfinite weights or malformed splits before accepted output.
A4. Version report schema with explicit evaluated_partition=test, test_evaluation_performed=true, loaded artifact SHA and tensor/calibration digests, input hashes, per-case IDs/groups/family/target, actual runtime decision, conditional probabilities and abstention. Retain backwards compatible reading of prior reports by schema/version; do not mutate old reports or reinterpret stored provenance. Training run --config remains backwards compatible.
A5. Atomic unique output: stage, verify, fsync/rename; refuse overwrite and handle interruption/partial writes. A second run with same fixed inputs may target a NEW empty output path, and must produce semantically identical deterministic result fields. Resource/host timings live separately from deterministic content digest.

**A acceptance**: fail-trainer trap proves training unreachable; byte-mismatched input fails before scoring even with 1e-14 numeric change; successful fixed artifact evaluated with identical SHA before/after and correct test IDs. Original v1/v2 artifacts and train CLI remain supported. No test data used in fitting.

## B. Build a complete versioned independent evaluation/qualification analyzer

B1. Add a NEW analyzer entrypoint (for example scripts/qualify_semantic_v2.py). Leave scripts/analyze_m014_qualification.py unchanged because its source hash is in the frozen M014 manifest. Serialized missing-true flag may be interpreted only for explicitly identified legacy M014 schema AND matching frozen test-ID/partition evidence; explicit false is never considered evaluated. On new reports require explicit true and partition=test.
B2. Binary group aggregation: group maps to list of all per-case (case ID, truth, score), and both counterfactual rows MUST be present in the SAME group. Pair candidate and control by the identical case IDs, not insertion order; reject duplicates/missing/extra rows. Define group-mean or case-weighted Brier estimate in a future preregistration, and resample WHOLE leakage groups (10,000 deterministic draws; predeclared one-sided multiplicity adjustment); never bootstrap each paired row as independent. Implement reference calculation and test uneven group sizes/constant and skewed cases.
B3. Choice: pair the same option IDs and eligible answerable case IDs across models. Separate raw argmax correctness, actual thresholded final decision correctness, abstention/no-answer recall, answerable coverage and selective risk. Counterfactual success requires BOTH actual final answers correct (a correct raw choice that abstains does not pass). Support no-answer targets without constructing an extra option. Validate valid option permutations and case/order invariance.
B4. Require every manifest-named Binary family/Choice required OOD family plus controls (Binary train prior + legacy; Choice legacy, cross, always yes/no, always answer/abstain, and any declared variants) measured on identical eligible groups. Enforce independently counted answerable group minima >=50, no-answer group minima >=20, valid pair counts, no unknown required family and no missing control. No vacuous positive for empty arrays or missing numeric thresholds.
B5. Pairwise group CI lower/upper and direction correct; Bonferroni or other multiplicity policy read strictly from a **prospectively frozen** manifest. Parse metrics, threshold precedence and finite bounds. Invalid provenance/data => invalid; supported critical regression => negative; insufficient/conflicting/straddling interval => indeterminate; positive ONLY if all required statistical, OOD, controls, no-answer, counterfactual and resource gates pass. Test n=49/50, 19/20, point improvement with straddling CI, one-group negative, always-abstain, mismatched identities and absent threshold.
B6. Resource gates and platform evidence must be real: 16MiB artifact maximum, max 128 Choice options, bounded p95/latency/cold-load/RSS, host/compiled build identifiers, three-host exact artifact decision parity. Missing required platform/resource evidence => not positive, never synthetic fabricated pass.
B7. Output machine-readable per-gate status/pass/fail/insufficient/invalid, support group IDs, per-family effect, confidence interval, comparator, frozen threshold origin, cohort/test membership hash, model artifact fingerprint and task verdict. Human summary reflects exactly the JSON; no retrospective selection.

**B acceptance**: constructed suite tests explicitly cover serde true/false/missing cases and exact test membership; two Binary case rows remain in one group and are counted once as a resampling unit; independently calculated CI agrees; Choice conditional vs final decision correctness and no-answer semantics are correct; removing any required family/control prevents positive; a complete positive constructed fixture passes and mutating one gate to fail stops positive.
